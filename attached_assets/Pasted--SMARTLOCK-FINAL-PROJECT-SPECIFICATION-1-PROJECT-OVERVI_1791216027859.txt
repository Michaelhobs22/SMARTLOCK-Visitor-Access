# SMARTLOCK — FINAL PROJECT SPECIFICATION

## 1. PROJECT OVERVIEW

SMARTLOCK is a QR-based visitor access management system for homes, apartments, dormitories, and rental properties.

The system allows a resident/property owner to create secure, time-limited visitor passes for individual guests. Each pass contains a unique access code and QR code. The resident can view, manage, and revoke passes, while a simulated smart lock validates visitor credentials and determines whether access should be granted or denied.

The goal is to make SMARTLOCK feel like a complete, polished, working smart-access product suitable for a university final project demonstration.

IMPORTANT:

Do NOT rebuild the application from scratch if an existing SMARTLOCK application/codebase is already present in this Replit project.

First inspect the existing codebase, understand its current functionality, preserve working features, and then improve/refactor/complete it.

Do not remove existing functionality unless it is broken or conflicts with the requirements below.

---

# 2. FINAL PROJECT GOAL

Transform the current SMARTLOCK application into a polished, reliable, demonstration-ready final project.

The application should allow the complete flow:

Resident Dashboard
→ Create Visitor Pass
→ Configure Guest + Expiration + Pass Type
→ Generate Access Code + QR Code
→ View Pass
→ Share/Copy Pass
→ Visitor enters/scans credential
→ Smart Lock validates credential
→ Access Granted or Access Denied
→ Pass becomes Used when appropriate
→ Resident can monitor/revoke passes

Everything included in the final demonstration must work reliably.

# 5. ACCESS CODE GENERATION

Every visitor pass must receive a unique access code.

Requirements:

* Codes must be difficult to guess.
* Do not use sequential codes such as 000001, 000002, etc.
* Generate a random code.
* Avoid duplicate active codes.
* Display the code clearly.
* Provide a Copy button.

Example format:

SL-7K4P92

or another secure readable format.

The exact format may be chosen by the implementation.

# 6. QR CODE GENERATION

Every visitor pass must automatically receive a QR code.

The QR code should encode enough information for the application to identify the visitor pass.

Prefer encoding a secure pass identifier/token rather than exposing unnecessary personal information.

The QR code should:

* Render clearly
* Be downloadable if practical
* Be easy to scan
* Be displayed on the pass page
* Correspond to the correct visitor pass

Do not generate a fake visual QR code.

It must contain real encoded data that the application can validate.

# 8. PASS STATUS SYSTEM

Implement a reliable pass lifecycle.

Possible states:

### ACTIVE

The pass:

* Exists
* Has not expired
* Has not been revoked
* Has not been used

### USED

The pass has successfully opened the simulated smart lock.

A single-use pass must not be usable again.

### EXPIRED

The current time has passed the expiration time.

Expired passes must automatically be rejected.

### REVOKED

The resident manually revoked the pass.

Revoked passes must always be rejected.

Status should be calculated reliably rather than relying only on a manually stored status.

For example:

If a pass is ACTIVE but its expiration time has passed, the UI should display EXPIRED.

# 11. SECURITY / VALIDATION

Implement proper validation.

The system must reject:

* Empty access codes
* Invalid access codes
* Expired passes
* Revoked passes
* Already-used passes

* whether the pass exists
* whether it is expired
* whether it is revoked
* whether it is already used
* whether access should be granted

Use the same validation logic throughout the application.
